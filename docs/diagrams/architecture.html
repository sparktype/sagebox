sagebox 현재 구현

에이전트가 MCP 서버나 디버그 명령을 띄울 때만 비밀을 환경변수로 주입하는 로컬 데몬입니다. 볼트(SBX2), 관리 CLI, Unix 데몬, exec, sagebox MCP 서버와 .envrc를 대체하는 sagebox run까지 구현된 상태를 네 장으로 나눠 그렸습니다.

01 · Architecture · trust boundary

구성 요소와 신뢰 경계

관리 CLI는 데몬을 거치지 않고 패스프레이즈로 볼트를 직접 고칩니다. 그래서 세션이 풀려 있어도 에이전트는 정책을 바꿀 수 없습니다. 에이전트가 고를 수 있는 것은 프로필 이름뿐이고, 명령(argv)은 볼트 안의 프로필에 고정돼 있습니다. execve 이후에는 같은 프로세스가 MCP 서버가 되어 에이전트와 stdio로 대화합니다. 비밀은 그 프로세스의 환경변수에만 존재합니다. 같은 UID 안의 악의적인 프로세스는 격리하지 않습니다(SPEC.md의 위협 모델 참고). 프로젝트별 네임스페이스를 쓰면 이 그림 전체(데몬, 볼트, 감사 로그)가 ~/.sagebox/ns/<name>/마다 한 벌씩 따로 존재하므로, 한 프로젝트를 풀어도 다른 프로젝트는 잠긴 채로 남습니다. 에이전트가 띄우는 sagebox mcp serve는 비밀 이름·만료일·프로필과 잠금 상태만 돌려주는 조회용 서버입니다. 대신 살아 있는 동안 데몬에 Attach 임대를 잡아 두고, 이 임대가 sagebox run을 허용하는 조건이 됩니다(03 참고).

02 · Sequence · unlock → exec

세션 잠금 해제부터 execve까지

데몬은 첫 exec나 unlock에서 자동으로 뜹니다. 잠겨 있으면 exec가 Touch ID(없으면 GUI 대화상자의 패스프레이즈)로 묻습니다. exec 연결은 응답 뒤에도 닫지 않습니다. 클라이언트가 그 소켓을 물려준 채 execve하므로, MCP 서버가 살아 있는 동안이 곧 임대 기간입니다. 마지막 임대가 끝나고 30초가 지나거나 8시간이 되면 데몬은 DEK를 지우고 종료합니다. 감사 로그를 쓰지 못하면 ARGV + ENV를 보내지 않습니다.

03 · Sequence · sagebox run gate

sagebox run: MCP 서버가 떠 있을 때만 .envrc 대신 env 주입

sagebox import-env가 .envrc의 비밀 줄을 프로젝트 네임스페이스의 shell_env로 옮기고 파일에서 지웁니다. 그래서 잘못 커밋될 비밀 파일이 남지 않습니다. 데몬은 Touch ID를 묻기 전에 먼저 Attach 임대를 확인하므로, Claude Code(와 sagebox MCP 서버)가 없으면 인증 창 없이 바로 거부합니다. 값은 셸이 아니라 execve한 디버그 프로세스의 환경변수에만 들어갑니다. 이 게이트는 정책일 뿐 보안 경계는 아닙니다. 같은 UID의 프로세스는 직접 sagebox mcp serve를 띄울 수 있고, 에이전트가 sagebox run -- env처럼 값을 출력하는 명령을 돌리면 값이 대화에 남습니다. 실제 방어선은 사용자 확인(Touch ID)과 감사 로그의 run 기록입니다.

04 · Layer stack · envelope encryption

볼트 봉투 형식 (SBX2)

슬롯은 모두 32바이트 KEK를 얻어 같은 DEK를 푸는 방식이라, 하드웨어 슬롯을 추가해도 본문은 다시 암호화하지 않습니다. 모르는 kind의 슬롯은 해석하지 않고 그대로 보존합니다. 그래서 macOS에서 추가한 슬롯이 Linux에서 저장할 때 지워지지 않습니다. 패스프레이즈 슬롯은 항상 존재하며 복구 경로 역할을 합니다.
